# 斗棋竞技场（军棋白板版）- 产品需求文档

## Overview
- **Summary**: 一个支持联网对战的军棋游戏平台。核心引擎采用"白板棋子"设计（等级 0-9，高级吃低级），服务端权威裁定，暗棋信息严格隔离。后续可平滑扩展为《斗棋竞技场》的自定义棋子/锻体/符文系统。
- **Purpose**: 提供一个可扩展的军棋对战框架，第一版验证白板棋子 + 等级点分配玩法，为后续多维属性系统预留接口。
- **Target Users**: 两名联网对战玩家，通过浏览器客户端进行暗棋对战。

## Goals
- 实现纯逻辑军棋引擎（白板棋子版），通过单元测试
- 实现联网平台（账号、游戏ID、房间、服务端裁定、暗棋隔离、排行榜）
- 实现暗黑魔幻 + 东方符箓风格的前端界面
- 所有扩展点（数据配置、碰撞接口、布局阶段、等级字段）预留到位

## Non-Goals
- 气运值系统的实际数值逻辑（仅留字段和排行榜基础版）
- 战绩/复盘的完整功能（仅留存储扩展位）
- 音效资源的实际文件（仅预留接口）
- 移动端适配（桌面浏览器优先）
- 观战模式
- 段位/赛季系统

## Background & Context
- 参考项目：`wenxf94/XiangQi-Online`（军棋规则、Socket.IO 通信）、`BitByBitG/siguo-junqi`（棋子数据表、碰撞结算、房间系统）
- 军棋棋盘 12 行 × 5 列 = 60 个停靠点
- 传统军棋的司令到排长全部替换为"白板棋子"，第一版只有一个"等级"数值
- 架构原则：服务端权威，客户端只发操作请求；暗棋信息绝不泄露

## Functional Requirements

### 游戏引擎（任务一）
- **FR-1**: 棋盘为 12 行 × 5 列，共 60 个停靠点；格子类型为公路、铁路、行营、大本营。
- **FR-2**: 连接线规则：公路走一格；铁路直线不限格；工兵在铁路上可拐弯。
- **FR-3**: 每方 25 枚棋子：军旗×1、地雷×3、炸弹×2、工兵×3（特色棋子共 9 枚）；白板棋子×16 枚。
- **FR-4**: 白板棋子仅含"等级"数值（0-9）；等级高者吃等级低者，同级同归于尽；初始等级为 0。
- **FR-5**: 布阵阶段玩家可用 100 等级点给白板棋子分配等级。
- **FR-6**: 所有棋子可改名（≤3 字），名字仅己方可见，对方永不可见；局内随时可改，不消耗资源不占回合。默认名：特色棋子为"军旗/地雷/炸弹/工兵"，白板棋子统一为"白板"（16 枚可重名）。
- **FR-7**: 碰撞规则：炸弹碰任何棋子同归于尽；地雷被工兵碰则地雷死工兵活，被炸弹碰同归于尽，被其他棋子碰则来犯者死地雷活；军旗被任何棋子碰到则该方输。
- **FR-8**: 移动规则：公路一格、铁路直线不限格、工兵铁路可拐弯、行营为安全区（敌方不可攻击营内棋子）、地雷不可移动。
- **FR-9**: 布局合法性校验：军旗必须在大本营、地雷必须在后两排、炸弹不能在第一排、行营不能放子。
- **FR-10**: 棋子属性用数据表定义（`piece-rules.json`），不硬编码等级链。
- **FR-11**: 碰撞结算走统一接口 `resolveCombat(attacker, defender)`。
- **FR-12**: 棋盘用配置文件（`board-config.json`）。
- **FR-13**: 等级字段设计为可扩展结构（如 `{ rank: 3 }`），后续可替换为多维属性对象。
- **FR-14**: 布局阶段预留接口，后续可加"资源分配 + 成长方向选择"。

### 平台（任务二）
- **FR-15**: 账号注册/登录，密码 BCrypt 哈希存储，账号数据持久化（JSON 文件）。
- **FR-16**: 每个账号有唯一游戏ID，与用户名分离；游戏ID 可自定义但必须唯一。
- **FR-17**: 房间系统：创建房间、通过房间码加入、房主准备后开始、断线重连。
- **FR-18**: 服务端权威裁定：客户端只发操作请求，服务端校验合法性并运行游戏引擎。
- **FR-19**: 状态同步：每次操作后向双方分别发送各自可见的状态。
- **FR-20**: 暗棋信息隔离：服务端绝不发送敌方暗子完整数据，绝不发送敌方棋子名字；碰撞结果只通知"谁吃谁/同归于尽/被地雷炸"，不暴露被吃棋子完整信息。
- **FR-21**: 数据存储层统一管理账号、房间、对局记录，字段为战绩/气运值/排行榜/复盘留扩展位。
- **FR-22**: 排行榜基础版：全服排名，显示游戏ID、气运值、胜场数，从账号模块读取排序。
- **FR-23**: 前端界面：登录/注册、房间列表/房间码输入、等待界面、对局界面（棋盘居中、左侧预留、右侧操作面板、顶部栏、底部聊天栏）、排行榜、个人主页。
- **FR-24**: 前端视觉风格：暗黑魔幻 + 东方符箓（深色底、暗金线条、棋子光晕、石质棋盘、符文悬浮）。

## Non-Functional Requirements
- **NFR-1**: 游戏引擎为纯 TypeScript，无运行时依赖，可在服务端和客户端复用。
- **NFR-2**: 服务端使用 Node.js + Express + Socket.IO。
- **NFR-3**: 前端使用 React + Vite + TypeScript，棋盘用 Canvas 渲染粒子/动画，UI 面板用 DOM/CSS。
- **NFR-4**: 暗棋信息隔离在服务端序列化层强制保证，不依赖客户端自觉。
- **NFR-5**: 碰撞结算逻辑与棋子定义数据解耦，便于后续替换为多维属性对砍。

## Constraints
- **Technical**: 纯逻辑引擎不依赖任何第三方库；后端密码哈希使用 bcryptjs；实时通信用 Socket.IO。
- **Business**: 名字≤3字、白板棋子等级 0-9、每方 100 等级点。
- **Dependencies**: Node.js 环境、npm 包管理。

## Assumptions
- 两名玩家通过两个浏览器窗口进行本地测试（服务端运行在本地）。
- 账号数据用 JSON 文件存储即可满足交付，后续可替换为 SQLite。
- 前端使用 Canvas 绘制棋盘格线和棋子，UI 交互用 React 组件。
- 断线重连基于 socket.id + 房间码 + 账号 token 恢复。

## Acceptance Criteria

### AC-1: 棋盘数据结构正确
- **Type**: `rule`
- **Given**: 加载 `board-config.json`
- **When**: 构建棋盘
- **Then**: 棋盘为 12×5=60 点，每点有正确的类型（公路/铁路/行营/大本营）和连接关系
- **Pass Condition**: 单元测试验证 60 个点、各类型数量、连接关系正确
- **Evidence**: `engine.test.ts` 中棋盘结构测试通过

### AC-2: 棋子数据表驱动
- **Type**: `rule`
- **Given**: 加载 `piece-rules.json`
- **When**: 查询棋子属性
- **Then**: 特色棋子和白板棋子定义可从数据表读取，无硬编码等级链
- **Pass Condition**: 棋子类型、数量、默认属性均来自 JSON
- **Evidence**: 代码中无 `if (type === 'commander')` 等级链硬编码

### AC-3: 白板棋子等级碰撞
- **Type**: `rule`
- **Given**: 两枚白板棋子等级分别为 a 和 b
- **When**: 调用 `resolveCombat`
- **Then**: a>b 则 a 存活 b 死；a<b 则 b 存活 a 死；a=b 则同归于尽
- **Pass Condition**: 覆盖所有大小比较场景的测试通过
- **Evidence**: `combat.test.ts` 中白板碰撞测试通过

### AC-4: 特色棋子碰撞规则
- **Type**: `rule`
- **Given**: 特殊棋子（军旗/地雷/炸弹/工兵）参与碰撞
- **When**: 调用 `resolveCombat`
- **Then**: 炸弹同归于尽、地雷规则、军旗被碰即输、工兵吃地雷
- **Pass Condition**: 所有特色棋子碰撞组合测试通过
- **Evidence**: `combat.test.ts` 中特色棋子测试通过

### AC-5: 移动规则
- **Type**: `rule`
- **Given**: 棋子在棋盘某位置
- **When**: 请求移动到目标位置
- **Then**: 公路一格可达、铁路直线不限格可达、工兵铁路拐弯可达、地雷不可移动、行营安全
- **Pass Condition**: 各移动规则测试通过
- **Evidence**: `movement.test.ts` 通过

### AC-6: 布局合法性校验
- **Type**: `rule`
- **Given**: 玩家提交布局
- **When**: 校验布局
- **Then**: 军旗在大本营、地雷后两排、炸弹不在首排、行营空
- **Pass Condition**: 合法布局通过、非法布局被拒绝
- **Evidence**: `layout.test.ts` 通过

### AC-7: 等级点分配
- **Type**: `rule`
- **Given**: 16 枚白板棋子初始等级 0
- **When**: 玩家分配 100 点
- **Then**: 总和不超过 100、每枚等级 0-9、分配后可碰撞
- **Pass Condition**: 分配总和校验、等级范围校验通过
- **Evidence**: `layout.test.ts` 中等级分配测试通过

### AC-8: 改名功能
- **Type**: `rule`
- **Given**: 己方棋子
- **When**: 修改名字（≤3字）
- **Then**: 名字更新；对对方状态序列化时不包含该名字
- **Pass Condition**: 改名成功、对方视图中无该名字
- **Evidence**: `rename.test.ts` + 序列化隔离测试通过

### AC-9: 扩展接口预留
- **Type**: `rubric`
- **Dimension**: 可扩展性
- **Scale**: 1-5
- **Anchors**: 1 = 硬编码无扩展点；3 = 有配置文件但接口不统一；5 = 数据表驱动 + 统一碰撞接口 + 可扩展等级结构
- **Pass Threshold**: >= 4
- **Evidence**: 代码审查：`piece-rules.json`、`board-config.json`、`resolveCombat` 统一接口、`{ rank }` 结构

### AC-10: 账号注册登录
- **Type**: `rule`
- **Given**: 用户名和密码
- **When**: 注册后登录
- **Then**: 注册成功存储 BCrypt 哈希；登录校验通过返回 token；游戏ID 唯一
- **Pass Condition**: 注册/登录 API 测试通过，密码不以明文存储
- **Evidence**: 后端账号测试 + 前端登录流程可用

### AC-11: 房间与对局流程
- **Type**: `rule`
- **Given**: 两个玩家
- **When**: 一方创建房间，另一方凭房间码加入，双方准备
- **Then**: 进入对局；断线后可凭房间码 + token 重连
- **Pass Condition**: 两窗口可创建/加入/开始/重连
- **Evidence**: 手动测试 + Socket 事件日志

### AC-12: 服务端权威裁定
- **Type**: `rule`
- **Given**: 客户端发送非法走子
- **When**: 服务端校验
- **Then**: 拒绝非法操作，合法操作由服务端引擎裁定后广播结果
- **Pass Condition**: 非法操作被拒绝、合法操作状态正确同步
- **Evidence**: 服务端校验测试 + 抓包验证

### AC-13: 暗棋信息隔离
- **Type**: `rule`
- **Given**: 对局进行中
- **When**: 服务端向玩家 A 发送状态
- **Then**: 不包含玩家 B 暗子的完整数据和名字；碰撞结果不泄露被吃棋子完整信息
- **Pass Condition**: 序列化输出中无敌方暗子 `name`、`rank` 等字段
- **Evidence**: `serialization.test.ts` 中敌方棋子字段检查通过

### AC-14: 排行榜
- **Type**: `rule`
- **Given**: 多个账号有不同气运值和胜场
- **When**: 请求排行榜
- **Then**: 按气运值降序排列，显示排名、游戏ID、气运值、胜场
- **Pass Condition**: 排序正确、字段完整
- **Evidence**: 排行榜 API 测试通过

### AC-15: 前端视觉风格
- **Type**: `rubric`
- **Dimension**: 暗黑魔幻 + 东方符箓风格还原度
- **Scale**: 1-5
- **Anchors**: 1 = 无风格；3 = 基本配色到位；5 = 完整实现石质棋盘、暗金线条、棋子光晕、行营/大本营光效、碰撞动画
- **Pass Threshold**: >= 4
- **Evidence**: 浏览器截图审查

### AC-16: 能模拟一整局
- **Type**: `rule`
- **Given**: 两名玩家完成布局
- **When**: 轮流走子直至一方军旗被碰
- **Then**: 游戏正常结束，胜负判定正确
- **Pass Condition**: 端到端对局测试通过
- **Evidence**: `game.test.ts` 整局模拟 + 两浏览器窗口实测
